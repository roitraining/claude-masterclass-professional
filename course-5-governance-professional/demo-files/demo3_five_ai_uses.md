# Demo 3 Sample: Five AI Uses to Tier

Use `risk_tier_scale.md`. For each use, decide the tier, any status flag (not permitted as practiced, shadow, changed), the deciding fact, and the review route.

## The five uses

**Use A: Blog drafts.** Marketing staff ask Claude Enterprise to draft blog posts from published product sheets. An editor reads and edits every post before it is published.

**Use B: Ticket summarizer.** Several Support agents installed a browser extension that summarizes open customer tickets. Tickets contain clinic contact details, order notes, and sometimes health-related details a clinic typed in. IT did not approve the extension and cannot name its vendor.

**Use C: Candidate ranking.** The applicant tracking vendor switched on an AI feature that ranks candidates. Recruiters in Ohio and Dublin read the top 20 and rarely open the rest.

**Use D: Code assistant.** Engineers use Claude Code on internal repositories in the company configuration. Every change goes through a pull request that a second engineer reviews.

**Use E: Renewal emails.** Sales reps paste contract excerpts, including Halvern's, into a free chatbot account on a personal phone to draft renewal emails.

## Intake form (route a new use to the right review)

A new use answers these seven questions. The answers set the tier.

1. What is the work, in a sentence?
2. Which data classes go in? (Public, Internal, Confidential, Regulated)
3. Does the output affect a person's hiring, pay, discipline, or access to a service?
4. Does any output leave the company without full human review?
5. Does a customer contract or employee representative agreement apply?
6. Who is the named owner?
7. Is the tool already approved, or is it new?

Any yes to question 3, any Regulated answer to question 2, or any yes to question 5 sends the use to Tier 3.
